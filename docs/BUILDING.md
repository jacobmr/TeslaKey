# Building from source

These instructions produce a debug APK for development and evaluation. A debug
APK is not a permanent public release artifact.

## Requirements

- Git
- Android Studio with Android SDK 35
- Java 17 or later
- Android SDK Platform Tools for `adb`

The Gradle wrapper downloads the required Gradle distribution and build
dependencies.

## Clone

```bash
git clone https://github.com/jacobmr/TeslaKey.git
cd TeslaKey
```

The `upstream` history and GPL attribution are included in the repository.

## Build and verify

On macOS, Android Studio's bundled JDK can be selected with:

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
```

Run unit tests, build the debug APK, and run Android lint:

```bash
./gradlew testDebugUnitTest assembleDebug lintDebug
```

Build the optimized release variant as an additional check:

```bash
./gradlew assembleRelease
```

Expected debug APK:

```text
app/build/outputs/apk/debug/app-debug.apk
```

The release variant is unsigned unless you explicitly provide a signing
configuration.

## Inspect the APK

Calculate a SHA-256 digest before moving an APK between devices:

```bash
shasum -a 256 app/build/outputs/apk/debug/app-debug.apk
```

Android SDK Build Tools can verify the APK signature:

```bash
apksigner verify --verbose --print-certs \
  app/build/outputs/apk/debug/app-debug.apk
```

The debug signer is automatically generated by Android development tools and is
not suitable for a durable public release.

## Install the debug build

After pairing and connecting to the watch over Wi-Fi:

```bash
adb -s WATCH_IP:CONNECTION_PORT install -r \
  app/build/outputs/apk/debug/app-debug.apk
```

Replace `WATCH_IP:CONNECTION_PORT` with the address shown on the watch's main
Wireless debugging screen. See [Installing TeslaKey](INSTALL.md) for the full
pairing flow.

## Signing a durable release

Android requires all APKs to be signed. Every TeslaKey update must use the same
signing certificate as the installed version or Android will reject it.

To create a signed APK with Android Studio:

1. Open the project in Android Studio.
2. Select **Build → Generate Signed Bundle/APK**.
3. Select **APK**, then **Next**.
4. Select the `app` module.
5. Select an existing release keystore or choose **Create new**.
6. Store the keystore **outside this repository**.
7. Choose the `release` build type and create the APK.
8. Verify the signed artifact with `apksigner`.
9. Back up the keystore and its recovery information securely.

Follow Android's official
[app-signing guidance](https://developer.android.com/studio/publish/app-signing).

Never commit:

- a `.jks` or `.keystore` file;
- signing passwords;
- a private key;
- `key.properties` containing credentials; or
- a copied debug keystore.

Losing the release key prevents normal updates. Changing the signing key forces
users to uninstall, destroys their enrolled watch credential, and requires
vehicle re-enrollment.

## Release checklist

Before distributing a release APK:

1. update `versionCode` and `versionName` in `app/build.gradle`;
2. run unit tests, lint, debug build, and release build;
3. inspect the final manifest and confirm only NFC permission is requested;
4. sign with the established release key;
5. verify the signature and record the APK SHA-256;
6. install the exact signed APK on a physical watch;
7. test enrollment, B-pillar lock/unlock, and drive authorization;
8. keep an authorized physical card available throughout testing;
9. write release notes that call out security or compatibility changes; and
10. publish the SHA-256 with the release artifact.
